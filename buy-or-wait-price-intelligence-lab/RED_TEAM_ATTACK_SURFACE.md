# Red-team attack-surface inventory

This inventory describes controls actually enforced by the remediation tree. It intentionally records gaps rather than treating a boundary as protected merely because it is documented.

| Input/state | Trust level | Validation/canonicalization boundary | Persistence | Can affect recommendation? | Fail-safe / review note |
|---|---|---|---|---|---|
| Barcode payload | Untrusted client input | `normalize_intake`; strips spaces/hyphens, accepts digits, validates supported lengths/checksum; an HTTP(S) barcode payload is routed to URL normalization | Normalized input only; captured offer may be stored | Yes, through identity resolution | Invalid values raise `ProductIntakeError`/HTTP 422; QR/URL semantics need adversarial review |
| GTIN/UPC/EAN | Untrusted identifier | `normalize_gtin`; check digit and length 8/12/13/14; GTIN-14 representation | Product identity after exact resolution | Yes | No fuzzy fallback for invalid checksum |
| ISBN-10/ISBN-13 | Untrusted identifier | ISBN-10 check and conversion to ISBN-13; ISBN-13 uses GTIN validation | Product identity after exact resolution | Yes | Invalid ISBN rejected; verify ISBN edge cases independently |
| Product URL | Untrusted client input | HTTP(S), non-empty host, no credentials/control characters, valid port; lowercase host and remove fragment | Canonical provenance URL only | Yes if an adapter resolves it | User URLs are not fetched by the API; no arbitrary redirect/SSRF control exists for a future fetcher |
| Redirects | Untrusted external state | No redirect following in current intake | None | Not currently | Any future URL fetch must add redirect limits, DNS/IP checks, and scheme enforcement |
| Retailer/marketplace URL | Untrusted external state | Host is preserved as provenance; Amazon ASIN extraction only for known path shapes | Normalized input/product provenance | Yes if identity resolves | Marketplace listing is not silently treated as canonical product; resolver/adapter must confirm variant |
| Uploaded image/image reference | Untrusted client input | Non-empty string, max 4096 characters; no image bytes processed in lab | Reference can be carried as intake evidence; no object store | Potentially through OCR adapter | No EXIF stripping, malware scan, retention, or signed upload URL exists yet |
| Image metadata/EXIF | Untrusted image content | No EXIF parser or sanitizer in current code | Not read by current lab | Not currently | Production upload adapter must strip location/device metadata before retention |
| OCR output | Untrusted derived evidence | Keys/values bounded and whitespace-normalized to max 512 chars; resolver may use brand/model/MPN evidence | Bounded evidence in normalized input; not financial state | Yes, via candidate ranking | Treated as inert data; hostile prompt text cannot execute, but OCR correctness is not proven |
| Visual-model output | Untrusted derived evidence | No live visual-model adapter exists | None | Not currently | Unresolved without a future explicit adapter and confirmation gate |
| Search terms/manual text | Untrusted client input | Trim/collapse whitespace; minimum length 2 for search; bounded metadata | Normalized input only | Yes, as low-confidence candidate evidence | Fuzzy/title-only resolution requires confirmation rather than guessing |
| Provider responses | Untrusted external data | ShopSavvy adapter validates object/list shapes, nested identifiers/specifications, Decimal money, timezone-aware timestamp, condition, explicit availability allow-list, currency, shipping, and provenance; malformed rows are rejected or quarantined; HTTP/rate-limit errors become connector errors | Trusted/corroborated rows only enter shared history; quarantined rows are not decision history | Yes | Unknown fields never default to new/in-stock/USD/now/free shipping; the engine independently excludes quarantined rows |
| Product title/description | Untrusted external/user data | Titles are normalized only for matching; no HTML/script execution | Product identity or evidence | Yes for fuzzy matching | Description is not an instruction channel; exact variant must still pass identity gate |
| Seller data | Untrusted provider data | Seller is carried as observation metadata; retailer/source restrictions can filter watches | Observation/watch provenance | Yes through offer selection | Seller reputation/risk is not independently modeled yet |
| Currency | Untrusted client/provider field | Intake and connector require 3 alphabetic characters; observation identity includes currency; engine uses distinct-currency counts, accepts only a unique dominant currency, and returns insufficient evidence for tied mixed currencies | Observation currency retained | Yes | No silent FX conversion or lexical tie-break; ambiguity is explicit in evidence/reason codes |
| Item price | Untrusted client/provider field | Intake and `PriceObservation.__post_init__` require finite, non-negative Decimal values | Observation and decision evidence | Directly | Invalid provider money becomes a connector normalization error; direct construction raises |
| Shipping | Untrusted client/provider field | Intake and `PriceObservation.__post_init__` require finite, non-negative Decimal values; landed cost is derived | Observation and decision evidence | Directly | Negative shipping cannot instantiate a domain observation |
| Landed price | Derived from price + shipping | `PriceObservation.landed_price`; engine selects/computes using Decimal | Stored as derived property, not independent mutable field | Directly | No tax normalization; taxes are explicitly outside current policy |
| Availability | Untrusted provider field | Provider uses an explicit recognized-state allow-list; known negative states become unavailable and unknown/missing states are quarantined/unavailable; engine/watch filters unavailable offers | Observation | Yes | Unknown availability cannot become trusted in-stock evidence |
| Condition | Untrusted provider/user enum | `Condition.UNKNOWN` plus accepted-condition sets; unknown ShopSavvy values are quarantined and never become NEW | Observation/watch | Directly | New/open-box/refurbished/used histories remain separate |
| Product variants | Untrusted candidate/evidence | Resolver protects storage/capacity, size, pack, bundle, edition, generation/year, carrier/region, model and GTIN differences | Canonical product and first-party observation context | Directly | Conflicting strong identifiers require confirmation; weak visual/title matches do not silently merge |
| Financial-result input | Untrusted public request plus trusted server-side seam | `FinancialSafetyProvider` is injected into `AppState`; missing state is 422; SAFE_NOW with non-FULL, future-dated, or contradictory evidence becomes non-buying/confirmation; as-of checks use financial/evaluation evidence time | Decision record keyed by authenticated subject in memory | Absolute effect | `NOT_AFFORDABLE` vetoes; `SAFE_LATER` and `SAFE_WITH_PLAN` cannot become BUY_NOW; fixture provider must be replaced by the real financial engine before deployment |
| Watch creation | Untrusted API caller | Authenticator resolves subject; Pydantic target/date/condition validation; service rejects empty conditions/negative target; explicit unknown product is 404 | Subject-keyed in-memory repository | Controls future alerts | Fixture bearer auth is test-only; durable tenant persistence remains deferred |
| Watch updates/refresh | Scheduler/provider state | Scheduler due-time interval; WatchService filters trust, freshness, condition, retailer/source and availability before persistence; trigger state deduplicates alerts | Watch state and eligible first-party history | Yes through alerts/reevaluation | No distributed locks or durable scheduler; process-local runtime remains a production gap |
| Scheduler execution | Internal state transition | `InMemoryWatchScheduler` runs due watches via injected refresh function | In-memory schedule | Yes | No purchasing action exists; production queue authorization and retry semantics are absent |
| Notifications | External target reference | No-op notification port stores opaque target reference and trigger event | Event list in test notifier | Indirectly | No actual notification provider or lock-screen redaction implementation |
| Persistence | Trusted application state but process-local | Product/decision/watch/observation repository interfaces; in-memory implementations key watches by user ID | Process memory only | Yes | No durable transactions, encryption, tenant auth, or crash recovery in lab |
| API parameters/body | Untrusted client input | Pydantic `extra=forbid`, enums, finite Decimal/date fields, timezone validators, non-empty supported watch conditions, selected bounds; FastAPI 422 on invalid data; domain service repeats money/condition validation | Request-derived normalized records | Yes | Global body size/rate limits and production token verification remain deployment work |
| Product/decision/watch identifiers | Untrusted path/header values | Product lookup is exact; decisions require authenticated subject ownership; watch repository key is `(subject, watch_id)` | Lookup only | Yes through object access | Unknown product/watch/decision fails 404; no fallback to first product |
| User/session identity | Untrusted request credential | `Authenticator` interface; canonical fixture form is `Authorization: Bearer fixture:<subject>`; legacy `X-User-Id` is explicitly test-only compatibility | Subject key for watches, private captures, and decisions | Directly controls access | Replace fixture authenticator with production token verification before internet exposure |
| Error responses/logging | Potentially sensitive derived state | FastAPI returns validation detail; provider adapter avoids logging keys | Response only; no structured logging layer | No, except information leakage | Review for provider/financial detail leakage once production logging/auth is added |
| Mobile API base/deep links | Client configuration/external input | `EXPO_PUBLIC_API_BASE` and text-driven action shell; no share extension/deep-link parser yet | None | Yes when connected | Provider secrets are absent; device build must test unsafe links, permissions, and state confusion |
